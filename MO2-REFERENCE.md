# MO2 reference - what Mod Organizer 2 does where the Patch Tagger touches it

Standing rule (the owner, 2026-09-23): before adding to or altering an MO2 feature, read MO2's own implementation at the
release tag and follow its shape. Read 2026-09-29 for MO2 **2.5.2** (the version the owner's instances run), for 1.0.1.

## Sources read

| Feature | MO2 source |
|---|---|
| renaming a mod | https://github.com/ModOrganizer2/modorganizer/blob/v2.5.2/src/modlist.cpp (`ModList::renameMod`: fixDirectoryName, the in-use check, `setName`, `modRenamed`), https://github.com/ModOrganizer2/modorganizer/blob/v2.5.2/src/profile.cpp (`Profile::renameModInAllProfiles`, `renameModInList`) |
| modlist.txt | https://github.com/ModOrganizer2/modorganizer/blob/v2.5.2/src/profile.cpp (`Profile::doWriteModlist`) |
| where an instance keeps its folders | https://github.com/ModOrganizer2/modorganizer/blob/v2.5.2/src/settings.cpp (`PathSettings::base`, `mods`, `profiles`, `getConfigurablePath`, `resolve`), https://github.com/ModOrganizer2/modorganizer/blob/v2.5.2/src/organizercore.cpp (`profilePath`, `modsPath`, `basePath`) |

## What MO2 does

| Feature | MO2 |
|---|---|
| renaming a mod | `ModList::renameMod` refuses an invalid name and one already used by another mod (case-insensitive), renames the folder (`ModInfo::setName`), then `modRenamed` rewrites the name in EVERY profile's modlist.txt: `Profile::renameModInAllProfiles` walks `Settings::paths().profiles()` - the configured profiles folder - and `renameModInList` swaps the name on each `+` / `-` line |
| modlist.txt | `# This file was automatically generated by Mod Organizer.` then one line per mod, highest priority first, `+` enabled, `-` disabled, `*` foreign; CRLF; UTF-8 |
| an instance's folders | ModOrganizer.ini's [Settings] `base_directory`, `mod_directory`, `profiles_directory` (defaults `%BASE_DIR%/mods`, `%BASE_DIR%/profiles`) may point anywhere. `IOrganizer::modsPath()` is the resolved mods folder, `profilePath()` the ACTIVE profile's folder; `basePath()` is only the base |

## What the Patch Tagger does, and how it follows MO2

| Feature | Patch Tagger |
|---|---|
| renaming a mod | the fast rename: the folders renamed on disk, every profile's modlist.txt rewritten the way `renameModInList` does (`+` / `-` lines, names compared case-insensitively, the file's own line ending kept), each list backed up first, then ONE `refresh(True)`; a target name that already exists is refused, as MO2 refuses it |
| an instance's folders | the mods folder is `modsPath()`; the profiles folder is the parent of `profilePath()` - the folder `renameModInAllProfiles` walks. Before 1.0.1 it was `basePath()/profiles`, which found no profiles on an instance whose profiles live elsewhere (Mo2/SSE/profiles - the Nexus report on MO2 Modlist Manager, 2026-09-29) |

## Departures

The rename does not go through `IModList.renameMod` one mod at a time: 350 calls timed MO2 out (the owner, 2026-09-22),
so the folders and lists are written directly and MO2 re-reads them in one refresh. The result on disk is what
`renameMod` + `renameModInAllProfiles` would write.
